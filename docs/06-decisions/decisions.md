# Decisions

| Decision | Reason | Date |
|---|---|---|
| Supabase for database | Serverless PostgreSQL with easy JS client | 2026-06-02 |
| No TypeScript | Faster development, smaller team | 2026-06-02 |
| No state management library | Simple app, React hooks sufficient | 2026-06-02 |
| Hardcoded API URL in frontend | No need for multi-environment config yet | 2026-06-02 |
| 0/1/2 attendance scoring | Supports Absent/Late/Present with simple math | 2026-06-02 |
| 4-term grading (PRELIMS → FINALS) | Standard Philippine HEI academic calendar | 2026-06-02 |
| End Semester restricted to Superadmin | Critical system action should be controlled by highest role | 2026-06-02 |
| Removed auto term/semester detection | Terms must be explicitly created by superadmin, not guessed from date | 2026-06-02 |
| React Context for teacher state | Eliminates redundant API calls; shared assignment selection across pages | 2026-06-02 |
| localStorage for assignment selection | Survives page refreshes; simple, no extra library needed | 2026-06-02 |
| Closed-term read-only enforced on both ends | Backend 403 + frontend disabled controls prevents accidental edits | 2026-06-02 |
| Subject `course_id = null` for department-wide | Simple nullable column avoids a many-to-many join table | 2026-06-02 |
| Archive mode via frontend term filtering | `GET /api/assignments` already returns all teacher assignments across terms; filtering by viewTerm on frontend avoids extra API calls and keeps the archive UI responsive | 2026-06-02 |
| Assignments are always additive (no "reassign" replace) | The unique constraint `(teacher_id, section_id, subject_id, school_year, semester)` prevents duplicates but allows the same teacher to have multiple subjects/sections; old data is never lost. Frontend UX makes this clear with grouped term views, deletion guards, and data-loss warnings. | 2026-06-02 |
| AdminContext for sharing term/archive state across admin pages | Before `AdminContext`, each admin page fetched `activeTerm` independently and had its own archive toggle logic. `AdminContext` centralizes activeTerm, allTerms, viewTerm, and isArchiveMode — same pattern as `TeacherContext` — eliminating redundant API calls and standardizing archive mode behavior across all admin pages. | 2026-06-02 |
| AdminTeachers assignment filtering by currentTerm | The "Assigned Course" column and View modal filter assignments by `currentTerm` instead of showing all terms at once. This matches the teacher-side UX where assignments are shown per-term, avoids confusion when many terms accumulate, and lets admins clearly see which teachers are active in the current/archive term. The API still returns all assignments; filtering is done in `useMemo` / in the fetch handler so no backend changes are needed. | 2026-06-02 |
| Teacher Settings page for archive management | A dedicated Settings page for teachers provides a clear, non-disruptive way to browse term history and enter/exit archive mode, matching the AdminSettings pattern and reducing clutter in the Dashboard and FloatingAssignmentSelector. | 2026-06-02 |
| Confirmation modal before archive mode entry (moved to TeacherSettings) | Prevents accidental archive mode switching — users must explicitly confirm they want to view a past term in read-only mode. The modal explains the restrictions before committing. Originally in FloatingAssignmentSelector, now only in TeacherSettings to keep the selector focused on assignment switching. | 2026-06-02 |
| TeacherLayout inner component pattern | Wrapping `TeacherLayoutInner` inside `TeacherProvider` (instead of having layout children also wrapped) follows the same pattern as `AdminLayout` and lets the layout directly consume context for the archive banner, eliminating prop drilling. | 2026-06-02 |
| TeacherContext `currentTerm` property | Adding `currentTerm = viewTerm || activeTerm` mirrors `AdminContext` so both contexts expose an identical API for term/archive display in layouts and reusable components. | 2026-06-02 |
| Grade-point scale as documented in `grade-point.md` | The numeric thresholds (98–100%, 95–97%, etc.) and classification remarks (Excellent, Very Good, etc.) are externalized to a doc file and implemented via a `GRADE_RANGES` lookup array. `gradeToPoint` returns a `{ gp, desc }` object so the remarks column shows meaningful descriptions. | 2026-06-02 |
| Activity feed scoped by department username list | Instead of relying on the `department` column in `activity_log` (which can be null/missing for superadmin entries), the admin GET handler queries `staff_users` for usernames in the admin's department and filters `activity_log` by `.in('user_name', ...)`. Superadmin usernames are explicitly subtracted from the list to prevent any cross-role visibility. | 2026-06-02 |
| One admin per department enforced in app code (superseded) | Originally the check was only done in `POST /api/users` and `PATCH /api/users/:id` by querying `staff_users` for an existing admin in the target department. Reversed on 2026-10-22 by adding a DB partial unique index. | 2026-06-02 |
| Student structured fields (first_name, last_name, mi, gender) with computed student_name | Replacing a single student name field with structured fields enables better display (Gender column), sorting, and import/export consistency. `student_name` kept as "Last, First M." computed column for backward compatibility with teacher pages (GradeSummary, ClassRecord, Attendance). | 2026-06-03 |
| Client-side Excel import with xlsx library | Avoids multer/file-upload backend complexity. The existing `xlsx` library (already a dependency) handles parsing client-side; only validated non-duplicate rows are sent to the backend. No backend file storage or streaming needed. | 2026-06-03 |
| Subjects persist across school years with nullable semester | Removing `school_year` from subject creation/filtering eliminates term-dependency duplication (same subject created every year). Subjects are now semester-scoped (1st/2nd Semester, Summer, All) and visible across all academic terms. | 2026-06-03 |
| DELETE student route at `/api/sections/students/:id` | Matches the existing frontend URL pattern. The route path does not include `:sectionId` because the frontend only has the student's UUID and not the section context at the call site. Cascade deletes component_scores and attendance records. | 2026-06-03 |
| Grade calculations extracted to `utils/gradeCalculations.js` | Eliminates 5 copy-pasted functions across 3 files. Single source of truth for transmutation formula `(total/maxTotal)*50+50`, weight logic, and final grade computation. | 2026-06-04 |
| `clampWarnings` state with auto-clear timeout | Provides temporary user feedback for value clamping (score exceeding max_score, weight exceeding remaining) without requiring a toast library. Auto-clears after 3 seconds. | 2026-06-04 |
| Grade computation stays in the frontend | The backend stores raw scores only. Single module `utils/gradeCalculations.js` shared by Class Record, Grade Summary, and Analytics keeps the formula in one place and avoids duplicating it in a second language. Trade-off: no server-side grade reporting. | recorded 2026-10-22 |
| AI via OmniRoute + strict JSON validation | The gateway is OpenAI-compatible, so the provider can be swapped without touching route code. Responses are schema-validated and rejected (502) rather than trusted, and the AI never writes grades. | recorded 2026-10-22 |
| Backup format v1.0 with `.backup.sg` + checksums | A magic header, format version, schema-compat date, and per-table SHA-256 checksums make partial/corrupt files detectable before restore. Categories with dependency closure let operators export only what they need. | recorded 2026-10-22 |
| AES-256-GCM + scrypt for backup encryption | Standard authenticated encryption; scrypt makes password guessing expensive. Minimum 8-character password is enforced before encryption. | recorded 2026-10-22 |
| 1-day JWT with no refresh token | Simple session model for a demo/MVP; users log in daily. No revocation list, so deleting a user does not invalidate their existing token until it expires. | recorded 2026-10-22 |
| Open CORS (`app.use(cors())`) | Acceptable for a local/demo deployment; must be restricted before public hosting. | recorded 2026-10-22 |
| No global backend error/404 middleware (superseded) | Originally Express defaults were accepted to keep route code simple. Reversed on 2026-10-22 — see "One JSON error shape + central handler". | recorded 2026-10-22 |
| Term-lock helpers duplicated per route file (superseded) | Each route family (`sections`, `assignments`, `gradingComponents`, `componentActivities`, `componentScores`, `attendance`) kept its own `checkTermClosed*` helper because each needed a different lookup path. Superseded on 2026-10-23 by the shared `middleware/termLock.js`. | recorded 2026-10-22 |
| PDF export via `jspdf` + `jspdf-autotable` in the browser | Reuses the table data already loaded, avoids server-side rendering dependencies, and keeps the backend free of export libraries. | recorded 2026-10-22 |
| 9-digit staff ID + derived username | A fixed-width institutional ID gives a stable, collision-resistant username (`lastname.NNNN@sg`) without asking operators to invent one. Enforced with a DB CHECK and unique index. | recorded 2026-10-22 |
| OpenCode project config points at `docs/AGENTS.md` | OpenCode V2 only auto-discovers `AGENTS.md` at the project root/ancestors; the docs-system file is nested under `docs/`, so an explicit `instructions` entry is needed to keep those rules always active. | 2026-10-22 |
| Shared read-access helpers in `backend/middleware/access.js` | Read endpoints were trusting any authenticated caller with a UUID. One policy keeps behavior consistent: superadmin sees all, admin is scoped to `created_by`, teacher to their own `teacher_id`/assignments. Helpers fail closed on missing ids or DB errors. Writes keep their inline teacher-only checks for now. | 2026-10-22 |
| Bulk score batches validate every row before writing | Checking only `scores[0]` let a mixed payload write into another teacher's assignment. Resolving every distinct activity → component → assignment first, then rejecting the whole batch, keeps the upsert atomic from an authorization standpoint. Term lock is likewise checked for every assignment in the batch. | 2026-10-22 |
| Activity identity comes from the JWT | `POST /api/activity` previously accepted `user_name`/`department` from the body, so any logged-in caller could write an audit row as someone else. Reading the signed JWT instead makes attribution trustworthy; `department` is the login-time snapshot already used by the other route-level audit inserts. | 2026-10-22 |
| One JSON error shape + central handler | Express default HTML for unmatched routes and raw `err.message` from routes made the API inconsistent and leaked DB internals. A catch-all 404, a 4-arg error middleware, and a `sendServerError` helper give every failure one `{ message }` shape while keeping details in server logs. Backup validation keeps its `{ ok, errors }` shape because it intentionally returns a list. | 2026-10-22 |
| One canonical, idempotent attendance migration | Four SQL files could each define a different unique constraint, so the deployed shape depended on apply order and the attendance upsert could fail. Consolidating them into `migrate_attendance_final.sql` — which drops legacy unique constraints by discovery, not by name, then adds the 6-column target — makes every partial state converge. Old files are deprecation notices so stale instructions cannot reintroduce the 5-column constraint. | 2026-10-22 |
| One admin per department now also enforced by DB | The app check remains for friendly 400s, but direct SQL and restores could bypass it. A partial unique index on `lower(trim(department))` where `system_role = 'admin'` closes that hole without preventing superadmin reassignment. | 2026-10-22 |
| DB constraints for score, weight, and term integrity | Scores, weights, and the active term were enforced only in UI/route code. `add_db_constraints.sql` adds CHECKs, partial unique indexes, and triggers as a backstop. Routes still validate first so users get a 400 instead of a 500. The migration aborts on existing violations instead of silently rewriting grades. | 2026-10-22 |
| RLS enabled deny-all with no policies | Supabase exposes `public` through PostgREST, and the frontend never uses a Supabase client. Enabling RLS on every table with no policies blocks `anon`/`authenticated` by default while `service_role` (BYPASSRLS) keeps the Express backend working. Rejected the alternative of writing role policies: there is no browser-side Supabase access to authorize, so policies would add risk without benefit. `anon`/`authenticated` also have no table grants, making direct access fail with `401 permission denied`. The `RLS Enabled No Policy` advisor stays INFO by design. | 2026-10-23 |
| Shared term lock + archive-header guard | Term writes were only checked in some route files, and tables without a term column (`staff_users`, `departments`, `courses`) could not be checked at all. `middleware/termLock.js` centralizes `assertActiveTerm` and adds `rejectArchivedWrites`, which rejects mutating methods whenever the client-declared viewed term (`X-View-Term-School-Year` / `X-View-Term-Semester`) is not active. This closes section/subject writes and archive-mode structural edits in one place without adding term columns to unrelated tables. Trade-off: the guard trusts client-declared headers for *which* term is being viewed, but only to be stricter — writes never gain access they would not otherwise have. | 2026-10-23 |
